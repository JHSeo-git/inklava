# ADR 002: shadcn/ui and source organization

The user requested shadcn/ui styles and primitives, with source folders organized by role. Use the official guide for existing Vite projects to introduce Tailwind CSS 4's Vite plugin and the shadcn CLI. This replaces ADR 001's plain CSS approach and flat `src/` layout. Preserve editing, rendering, camera behavior, and Pele's default diagram styles. [Official Vite installation guide](https://ui.shadcn.com/docs/installation/vite)

As of 2026-10-29, use `shadcn` CLI 4.23.0, Tailwind CSS and `@tailwindcss/vite` 4.3.3, and Base UI 1.9.0. Adopt the `base-nova` style, neutral colors, and CSS variable theme generated by `--base base --preset nova`. Initially, import only Button, Textarea, Label, and Badge from the official registry and compose them in app components. Own the generated source in this repository and remove the previous CSS component path. Textarea was subsequently replaced by CodeMirror under ADR 003. [shadcn CLI](https://ui.shadcn.com/docs/cli), [Base UI Button](https://ui.shadcn.com/docs/components/base/button)

The registry uses the shadcn organization's `cn` 0.5.0 for class merging. Do not add separate clsx or tailwind-merge paths. Self-host the CLI-added Geist Variable font from its package and apply it only to the app UI. Pin all direct dependencies, including the CLI, CSS tooling, and fonts, with exact versions and `bun.lock`. Recent npm releases and official maintainers were checked for shadcn, Tailwind, and Base UI; shadcn's documentation showed roughly 127,000 GitHub stars. These are maintenance and adoption signals, not substitutes for testing the app. [cn repository](https://github.com/shadcn-ui/cn), [shadcn repository](https://github.com/shadcn-ui/ui), [Tailwind repository](https://github.com/tailwindlabs/tailwindcss), [Base UI repository](https://github.com/mui/base-ui)

Organize source into `app/` for entry and routing, `components/` for workbench components, `components/ui/` for shadcn primitives, `hooks/` for React hooks, `lib/` for rendering, downloads, syntax colors, coordinate calculations, and utilities, and `styles/` for the global theme. Following the user's request, remove the initial `features/workbench/` layout and put app components directly under `components/`. Use kebab-case filenames such as `source-editor.tsx`, `render-diagram.ts`, and `use-viewport.ts`, while keeping conventional component and function identifiers. Place unit tests beside the logic they exercise. Add neither barrel exports nor compatibility paths. Map `@/*` to `./src/*` with TypeScript 7 `paths`, without `baseUrl`.

With Tailwind preflight enabled, explicitly prevent SVG max-width constraints and verify default fonts, strokes, and natural dimensions in the browser. In the original textarea implementation, override `field-sizing-content` with `field-sizing-fixed` and flex sizing so long input scrolls inside the panel. Rendering Base UI Button as a link assigns a button role, so apply `buttonVariants` directly to the not-found page's return link to retain link semantics. [Tailwind preflight](https://tailwindcss.com/docs/preflight)

Display only Inklava in the app header. The initial decision kept the description and Korean name in the README; a later request standardized documentation and UI copy on English. Use existing unit tests and Chromium, Firefox, and WebKit E2E tests to verify editing, errors, storage, pan, and zoom, including natural SVG sizing and panel behavior with long input. Physical trackpad feel and production deployment remain separate verification tasks.
