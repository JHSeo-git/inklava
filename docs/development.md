## Environment and checks

Use Bun **1.4.0** and Node.js **24.18.0 or later**. The baseline versions are recorded in `.bun-version`, `.node-version`, and `package.json`. Dependencies use exact versions and `bun.lock`.

```sh
bun run check                 # Formatting, type-aware lint, types, unit tests, and build
bunx playwright install chromium firefox webkit
bun run test:e2e              # Chromium, Firefox, and WebKit; starts the dev server as needed
bun run fmt                   # Apply Oxfmt's default style
bun run preview               # Preview the Vite build
```

Type checking uses the Go-based TypeScript 7 compiler through `tsc --noEmit`. Vite 8 and React plugin 6 provide Oxc transforms; Oxlint with `oxlint-tsgolint` provides type-aware linting, and Oxfmt handles formatting. The experimental Rust port, `tsrs`, was not adopted. See the [tooling research](research/tooling.md) for the rationale.

## UI and source structure

The app uses shadcn/ui's Base UI Nova style with Tailwind CSS 4. Button, Label, Badge, and Resizable are repository-owned sources generated by the official CLI. The source editor uses `@uiw/react-codemirror` with a theme based on the existing CSS variables. Panel resizing uses `react-resizable-panels` 4.15.1.

The theme lives in `src/styles/globals.css` and CLI configuration in `components.json`. Geist Variable is self-hosted for the app UI; Pele diagrams retain their default styles and fonts. To add a component, run the pinned CLI with `bunx shadcn add <component>`, pin any new dependency versions, and verify the result. See the [official Vite guide](https://ui.shadcn.com/docs/installation/vite).

The entry point is `src/app/main.tsx`. The `@/*` alias maps to `src/*`.

```text
src/
  app/                  # Entry point and router
  components/           # Workbench, source editor, and diagram preview
    ui/                 # shadcn primitives
  hooks/                # React hooks, including use-viewport
  lib/                  # Rendering, downloads, syntax colors, coordinates, and unit tests
  styles/               # Tailwind and shadcn theme
```

Use kebab-case source filenames such as `source-editor.tsx`, `render-diagram.ts`, and `use-viewport.ts`. Put app components directly under `components/`; do not create a `features/` layer. Component and function identifiers keep the usual React and TypeScript conventions. Documentation, UI copy, error messages, accessibility labels, and code comments are written in English.

## Test coverage and limits

Unit tests cover coordinate calculations and Mermaid token handling. Playwright tests across three browser engines cover error recovery, draft restoration and storage failure, composition events, indentation, undo/redo, search, Escape-then-Tab focus escape, search preservation during errors, label focus and selection, line-number alignment, internal scrolling, pointer-centered zoom and pan, camera preservation, initial fitting of hidden panels, resizing, mobile layout, and PNG exports.

Composition tests use synthetic events with English fixture labels to check event ordering and rendering delays. They do not replace testing with a real OS input method, including Korean IMEs. Trackpad sensitivity and inertial scrolling in macOS Safari also need physical-device testing.

The full Pele entry point, CodeMirror, and panel resizing produce an initial JavaScript bundle of about **1.50MB, or 518KB gzip**, triggering Vite's large-chunk warning. Code splitting and Web Workers have not been introduced. Large inputs can temporarily block the main thread; measure rendering latency on real devices before deciding on further optimization.
